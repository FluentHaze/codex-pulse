# 代码格式与注释约定

项目使用 Prettier 统一格式，Astro 页面由 prettier-plugin-astro 处理。

```bash
npm run format        # 整理桌面端、Electron、脚本、测试及官网源码
npm run format:check  # 只检查格式，不改文件
```

- 默认使用 2 空格缩进、单引号、分号，建议行宽为 100 字符。
- JSX、Astro 模板和 CSS 按结构展开，避免把多个业务区块挤在一行。
- 注释优先说明模块职责、数据来源、边界条件及设计原因；不逐行复述赋值或标签。
- 会话继承去重、未知计数、账号切换、异步响应失效、下载跳转及完整性校验等约束，应在对应代码旁解释。
- 不在注释或诊断输出中记录账号凭证、聊天正文或带临时签名参数的下载地址。
- 依赖目录、编译产物、发布包、二进制资源、锁文件和生成的流程图不手动格式化；排除规则见 `.prettierignore`。

提交前至少运行格式检查、自动测试和生产构建。修改更新传输时，还需运行 `npm run test:update-transport`，确保使用真实 Electron 覆盖跳转和取消行为。
