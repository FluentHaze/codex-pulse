# Codex Pulse

Windows / macOS 本地 Codex 额度监控，Electron + React + TypeScript。支持本地聊天的每轮 Token 用量查询，不发送模型对话，不保存登录 Token。

## 运行

需要 Node.js 22+，以及已安装、已登录 ChatGPT 账号的 Codex。Windows 自动从 PATH 和本机 Codex 安装目录查找 `codex.exe`；macOS 查找 PATH、Homebrew 常用路径、`~/.local/bin` 和系统或用户 Applications 下的 `Codex.app/Contents/Resources/codex`，也可在设置中选择可执行文件。通过 Finder 启动时通常不会继承终端的 PATH，使用 nvm 等自定义安装位置时可手动选择。

```powershell
npm install
npm run probe # 独立 app-server 真实额度读取，不输出账号邮箱或凭据
npm start
```

`npm run dev` 只用于页面开发；真实额度与系统交互需使用 Electron。

## 重置雷达与日历

「重置雷达」展示未来 24 / 48 小时额外全局重置的历史模型概率、最近重置及公告信号；预测为实验性参考，不代表官方承诺，也不替代个人账号的重置时间。

日历按本机时区展示历史公告记录，可切换月份、筛选已确认重置并点击日期查看来源。全局重置仅按来源接口 `group=reset` 且 `announcement_state=announced` 的记录标记；预告、储备重置与其他额度事件单独展示。服务端返回的个人窗口到期时间另设标记，不计入全局重置日。

公开数据来自 [codex-reset.com](https://codex-reset.com/)，使用其 [公开接口](https://codex-reset.com/developers)，通过 Electron 主进程读取，不发送账号、额度、聊天或登录信息。打开雷达时加载，每 5 分钟更新；主进程共享缓存，每个接口最多每分钟请求一次，并遵守 429 的 Retry-After。失败时保留上次成功数据并标注过期，首次失败显示不可用，不生成虚构概率或历史记录。

```powershell
npm test
npm run build
npm run pack
```

打包统一使用 Node.js 22.16 或更新版本（使用 nvm 时先执行 `nvm use`，项目已提供 `.nvmrc`），所有产物固定放在 `release/`：

| 命令 | 平台 | 输出 |
| --- | --- | --- |
| `npm run pack`（或 `npm run pack:all`） | Windows + macOS，需在 Mac 上运行 | `release/win/` 和 `release/mac/` |
| `npm run pack:win` | Windows x64 portable EXE | `release/win/` |
| `npm run pack:mac` | Mac arm64、x64 的 DMG 和 ZIP | `release/mac/` |

每次命令先构建源码，成功后递增一次补丁版本（如 `0.1.16 → 0.1.17`），同步更新 `package.json` 和 `package-lock.json`。双平台打包只递增一次，两端版本一致。采用 `主版本.次版本.补丁版本`；日常打包自动递增补丁版本，功能版本和重大版本由发布时另行调整。不自动创建 Git 提交或标签，也不上传发布。单独 `npm run build` 不递增版本。

安装包文件名包含版本与架构，保留旧版本安装包；解包后的应用目录会复用，请先退出其中运行的应用。并发打包会被阻止。若打包阶段失败，已生成的产物和本次版本号保留，重试会使用下一个版本；双平台其中一端失败时仍会尝试另一端，并最终报告失败。

应用启动后显示竖向圆环悬浮栏，点击额度进入详情和设置，右键打开菜单。托盘单击显示/隐藏，右键可关闭鼠标穿透或退出。关闭详情不会退出。

## macOS 运行和打包

在 Mac 上安装依赖后运行 `npm start`，额度连接可先通过 `npm run probe` 检查。菜单栏单击或右键打开菜单，移入显示额度卡片；桌面悬浮窗默认关闭，可在设置中开启；点击 Dock 图标打开详情，关闭详情后继续后台监控，使用菜单或 Cmd+Q 退出。

```sh
npm install
npm test
npm run pack:mac
```

`pack:mac` 需在 macOS 上执行，在 `release/mac/` 生成 arm64（Apple Silicon）和 x64（Intel）各自的 DMG 与 ZIP。将应用放入 Applications 后再开启登录启动。当前使用 ad-hoc 本地签名，打包时会对完整应用执行 `codesign --verify --deep --strict`，校验失败即停止生成安装包。本地签名可以验证包完整性，但没有 Developer ID 身份和 Apple 公证，下载后仍可能被 Gatekeeper 拦截；正式发行需另行配置 Developer ID 签名及公证。

macOS 实机需验收：自动/手动查找 Codex、登录和额度读取、浅色/深色菜单栏图标、Dock 激活、窗口拖动与穿透恢复、多显示器与全屏 Spaces、登录启动、休眠恢复和通知授权。Windows 构建和单元测试不能替代这些验收。

### Mac 首次安装与允许打开

Apple Silicon（M 系列）选择 `mac-arm64`，Intel Mac 选择 `mac-x64`。打开 DMG 后将 Codex Pulse 拖入「应用程序」；使用 ZIP 时先解压，再将应用拖入「应用程序」。

当前版本使用本地签名，尚未经过 Apple 公证。仅在确认文件来自本项目且未遭篡改时，按以下步骤允许打开：

1. 在「应用程序」中双击 Codex Pulse，先尝试打开一次。
2. 如果出现无法验证开发者或未公证的拦截提示，选择「取消」或「完成」。
3. 打开「系统设置 → 隐私与安全性」，向下找到「安全性」。
4. 在 Codex Pulse 被阻止的提示旁点击「仍要打开」，按提示使用密码或 Touch ID 验证。
5. 再次确认「打开」。系统通常会记住这次许可，后续可直接打开。

如果仍提示「已损坏」，或没有「仍要打开」，请使用最新版并反馈问题，不要直接关闭系统安全保护。签名完整性校验通过不等于 Apple 公证或系统准入验证。

参考：[Apple 官方说明：在 Mac 上安全地打开 App](https://support.apple.com/zh-cn/102445)。

## 数据和连接

使用官方 [Codex app-server 协议](https://learn.chatgpt.com/docs/app-server)，stdio 初始化后调用 `account/read` 与 `account/rateLimits/read`。独立进程复用本机 Codex 的默认账号环境；请在详情页核对脱敏账号与桌面端额度。如果桌面端使用其他账号或自定义 CODEX_HOME，两者可能不一致。

设置、脱敏账号、额度快照及通知去重记录保存在 Electron `userData/pulse.json`，诊断日志上限约 256KB，仅记录固定事件代码。不会复制登录凭据。查询超时为 20 秒，默认 5 分钟刷新，数据超过两个刷新周期标记过期；临时错误保留旧数据，登录和协议错误暂停自动重试，可登录或手动恢复。子进程连续启动失败后停止重启。

## Token 明细

在详情窗口点击「Token 明细」，选择本机聊天即可查看每轮输入、缓存输入、输出、推理及合计，最新轮次在顶部。列表显示用户消息摘要，点击「查看第 N 轮消息」可展开用户正文、助手进度说明与回复。未记录的正文会提示缺失；消息按纯文本显示，图片仅显示附件标记，不加载远程内容。当前聊天每 15 秒更新，也可点击「刷新记录」重新扫描聊天列表。默认读取 `CODEX_HOME/sessions` 或用户目录下的 `.codex/sessions`，支持选择其他 sessions 目录，列出可读取的全部用户聊天。

聊天列表及悬浮窗自动跟随会根据会话来源排除内部审核和子代理会话（如 `Guardian review`），过滤发生在项目筛选之前，不按标题文字匹配，也不会因此隐藏同名的正常用户聊天。若旧版固定跟踪了已被过滤的内部会话，请恢复自动跟随或重新选择用户聊天；程序不会静默替换固定目标。

支持普通 `.jsonl` 和 Zstandard 压缩的 `.jsonl.zst` 历史记录，流式解压且不落盘；同一路径同时存在两种格式时优先普通文件，避免重复计数。压缩记录的解压后大小同样限制为 256 MB。

统计来自本机 rollout JSONL 中的 `token_count` 累计事件，按轮次求增量并去重，不是对消息文字进行 Token 估算。一轮可以包含多次模型调用、工具结果和上下文输入；缓存输入已包含在输入中，推理已包含在输出中，合计采用记录提供的总量。继承的历史累计不会计入新轮次；无法恢复的统计、计数重置及损坏记录会标记缺失或不完整。没有结束事件的轮次显示「未结束」，不据此判断模型仍在运行。

这是本机历史，不代表当前登录账号的专属记录；不会读取其他电脑或云端尚未同步到本地的聊天，也不能据此精确换算订阅额度。消息正文和用量解析结果仅保留在本机内存，不上传、不另外写入文件。只展示用户与助手的消息，不展示系统指令、开发者指令、推理原文或工具调用输出。为限制内存，单条正文最多显示 32,000 字符、每轮最多 100 条，单次解析正文上限 2,000,000 字符，截断或省略时明确提示；Token 统计不受正文截断影响。单文件暂支持最大 256 MB；本地记录格式不是稳定的公开接口，Codex 升级后可能需要适配。

开发验证：`npx tsx scripts/probe-tokens.ts` 读取最近聊天的用量摘要，不输出聊天标题或正文。

## 今日用量和聊天筛选

「今日用量」按本机时区的当天用量事件汇总，显示合计、输入、输出、缓存输入、推理和轮次数，每 30 秒自动更新，也可手动刷新。跨午夜的同一轮按事件时间分别计入当天；缓存和推理不重复加到合计。相同轮次、时间和累计计数的分叉历史会去重，内部审核及子会话不计入。旧记录缺少时间、无法可靠去重或读取不完整时会显示提示。

今日统计读取所选 sessions 目录，不受聊天列表 200 条上限影响；仍属于本机记录，不能作为账号账单或订阅额度消耗比例。

「Token 明细」支持按标题或项目路径搜索、按项目筛选，并按更新时间筛选今天、近 7 天、近 30 天。条件可以组合，支持一键清空。搜索和筛选范围为所选目录中可读取的全部用户聊天；更新时间来自本地文件修改时间。

选择项目后默认显示匹配聊天的历史总用量，支持输入、输出、缓存和推理分项；选择具体聊天后显示该聊天逐轮明细。切换项目会清空聊天选择，汇总对可识别的分叉重复事件去重。更新时间筛选限定聊天集合，汇总仍为这些聊天的完整历史用量。

## 悬浮窗实时用量

竖向悬浮栏底部显示最近一轮 Token。后台每秒检查已跟踪文件的追加内容，仅解析轮次和用量事件，不为此请求模型或额度接口。每约 3 秒发现新聊天，默认跟随本机最近更新的记录；同时使用多个聊天时，在「Token 明细」选择聊天并点击「固定跟踪此聊天」，也可恢复自动跟随。

新轮次开始后清除上一轮数值，尚未收到用量事件时显示「—」，结束后标注「上轮」。这是本地用量事件落盘后的近实时显示，不是逐字生成 Token 计数，也不代表当前登录账号独有用量；模型推理或服务未更新统计时，数值可能暂时不变。悬停可查看额度窗口、重置时间和最近聊天；点击底部用量可进入 Token 明细。首次载入较大文件可能需要更久，实时解析只处理增量内容，正文不进入实时状态缓存。

悬浮栏宽 68 像素，按实际额度窗口数纵向排列圆环，底部 Token 以 k/m 简写。拖动顶部圆点或圆环区域可调整位置，超过 4 像素的拖动不会触发点击。鼠标移入时在有空间的左侧或右侧显示独立详情卡，移出后消失；拖动时隐藏详情卡，悬浮栏不改变尺寸。支持锁定位置和托盘恢复鼠标穿透，不再提供紧凑/标准模式切换。

无周额度时只展示实际返回的窗口，不根据 Pro/Plus 名称推断限制；缺失的整个窗口不显示，窗口存在但用量字段缺失时仍显示暂无数据。所有窗口都未返回时，不据此判定为无限额度。

## 外观与小时用量

默认采用深色主题，设置中可选择浅色或跟随系统，系统主题变化时自动更新。已有主题偏好继续保留。概览页可切换剩余/已用额度，并同步到悬浮圆环。设置修改后自动保存并显示反馈。详情页按 Ctrl+K（macOS 为 Cmd+K）打开快速操作，支持搜索页面、刷新额度、显示悬浮栏及切换主题；上下键选择，Enter 执行，Esc 关闭。

概览和今日用量页展示当天 0–23 时的 Token 柱状图，鼠标悬停或键盘聚焦可在浮层中查看每小时的精确数量；使用左右方向键切换小时，Home/End 跳到首尾，Esc 关闭提示。统计沿用今日用量的事件时间、跨文件去重和本机时区，缓存/推理不重复相加；夏令时回拨的同名小时合并显示。缺失计数不会显示为零，未来小时留空，记录不完整时显示提示。每 30 秒自动刷新，也可手动刷新。

## Windows 验收

- 通过 `npm run probe` 确认独立服务有权限读取，核对账号与桌面端额度。
- 启动应用检查悬浮窗、托盘、拖动、锁定、穿透恢复、详情关闭与显式退出。
- 断网/联网、休眠唤醒、账号切换、通知阈值及重启去重。
- 多显示器拔插、缩放、工作区边缘位置和开机启动。
- portable 打包不含数字签名，系统可能提示未知发布者；签名及安装包分发需另行配置。

不将静态检查或构建成功视为以上系统行为的验收证据。
